# Meridian Trust Bank — IT Change Management Policy

**Policy ID:** MTB-IT-POL-014
**Owner:** IT Infrastructure Manager
**Last Reviewed:** January 2026

## 1. Purpose

This policy establishes the process by which changes to Meridian Trust Bank's
production IT systems (network, servers, applications, and core banking
platform integrations) are requested, reviewed, and implemented, in order to
minimize the risk of service disruption.

## 2. Scope

This policy applies to all changes to production systems managed by the IT
Infrastructure and Applications teams, excluding routine password resets and
standard user account provisioning (see MTB-IT-POL-009).

## 3. Change Request Process

Any team member proposing a change must submit a Change Request (CR) through
the IT Service Desk ticketing system. The CR must include:

- A description of the change
- The systems affected
- The requested implementation date

Major changes (defined as changes affecting more than one branch location or
any core banking system) require sign-off from the IT Infrastructure Manager
before scheduling. Minor changes (single-system, single-location) may be
implemented by the assigned engineer once the CR is submitted, without
additional review, provided they are logged in the ticketing system.

## 4. Testing

Engineers are expected to test changes "to the extent practical" before
deploying them. A staging environment is available for the core banking
platform and should be used when time allows.

## 5. Implementation

Approved changes are implemented by the engineer who submitted the CR, during
the agreed maintenance window. The engineer notifies the IT Infrastructure
Manager via email once the change is complete.

## 6. Emergency Changes

In the event of a critical outage, engineers are authorized to make
whatever changes are necessary to restore service. These changes should be
documented in the ticketing system as soon as practical afterward.

## 7. Recordkeeping

The IT Service Desk ticketing system retains all Change Request tickets
indefinitely for reference.

## 8. Review

This policy is reviewed annually by the IT Infrastructure Manager.
